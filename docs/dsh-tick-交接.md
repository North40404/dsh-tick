## 消息路径（chat row）：不在本插件范围

设计稿 §8 原计划让 tick 兼任"消息路径"（收消息、聚合、决定什么时候回），**最终没有做，
也不该由 tick 做**——它属于另一个角色：

| 职责 | 归属 |
|---|---|
| 收消息、聚合、去重、唤醒判定、发送节奏 | **消息路径**（外部桥接或客户端） |
| 到点触发一次、注入 scratch、闸与配额 | **本插件** |

本插件的边界很硬：**它只往会话里投一条消息，不读消息、不认识 channel/群聊**（设计稿 D12）。
所以消息路径是否实现、用哪种实现，都不影响本插件工作。

## 解耦怎么验证（参考，不重要）

本包应当**不出现消息路径相关代码**。一条 grep 就能自查：

```powershell
Select-String -Path 'index.js','client.js','src\*.js' -Pattern 'message|channel|群聊'
```

2026-11-21 实测：命中的都是"往会话投递 prompt"这类本职代码，没有消息收发逻辑。

**为什么天然不耦合**：本插件做的事只有一件——到点往会话里追加一条提示。
它不关心这条提示之后被谁看到，也不关心有没有别的插件在往同一个会话里投东西。

## 「主动聊天任务」：用按钮代替 mode（2026-11-21 实现）

设计稿 §9.4 原本定义了 `mode: custom / chat`，切换时创建/停用预设任务。
**实际没做 mode**，改成任务列表下方一个「新建主动聊天任务」按钮：

- 点一下就建一条普通任务，**立刻可见、可改、可删**，没有隐藏状态
- 参数：`random 60~90 分钟`，`importance: normal`
- scratch：`这次只为聊天：想到什么就说，没话就什么都不说。`
- 不弹确认、不查重（用户要求：点按钮本身就是明确意愿，建错了删掉即可）

**为什么放弃 mode**：模式的实质是"全局开关 + 隐藏的预设任务"，
要额外协调"任务被用户改过/删了"、"切回来要不要重建"。用按钮直接建 job 更符合
tick 自己的模型——**一个 job = 一次机会 + 一个意图**。

**间隔为什么从 40~46 改成 60~90**：原参数是为群聊设计的。现在是一对一私聊，
且如果客户端支持系统通知，每次触发都可能弹一条，40 分钟一次等于一天二十多条。

## 必须知道的坑（都是真踩过的）

1. **本地 link 安装解析不到 `@deepseek-ai/schemastery`** → 不要 `export const Config`，
   配置存自己的 `settings.json`，校验走 `validatePatch`。
2. **`sessionController.list` 不过滤归档**（契约写 "visible" 但实测不成立）。
   归档集合唯一来源是 `workspaceController.follow()` baseline 帧的 `archivedSessionIds`。
3. **`sessionController.events` 的分页很反直觉**：
   - `maxMessages` **被忽略**，一次返回约 1400 条；
   - records 是**升序**（seq0 最旧）；
   - `beforeSeq` **必须传本页最旧的 seq**；用返回体的 `cursor`（= 最新 seq）会每页几乎重复，
     曾把 320 万算成 5100 万。
4. **删除任务必须用 `store.updateJob`（存在才更新）**，不能用 `putJob`：
   评估可能等空闲好几分钟，期间用户删了任务，`putJob` 会把它写回去。
5. **客户端渲染异常会白屏**：一处 TDZ 错误（`multiSession` 在 `jobRows` 之后声明）
   就让整个设置页消失，且**只在有任务时触发**（0 任务走空态分支不报错）。
   现在有 try/catch 兜底；改渲染逻辑后务必跑桩测试。
6. **不要用 PowerShell 字符串字面量 POST 中文**，会变 `?`。看到乱码先验字节。
7. **改完代码必须重载插件**：`plugin_manager set_bundle` 关→开。连续快速重载会
   `HMR transactions cannot be nested`，等几秒或重启 DSH。
